# CHANGELOG の毎回コンフリクトを merge=union で仕組みとして解消

- date: 2026-07-15

## やりたいこと

複数の PR がそれぞれ `docs/CHANGELOG.md` の `[Unreleased]` セクションへ追記する運用のため、
マージのたびに同じ箇所でコンフリクトが発生していた。これを人手ではなく Git の仕組みで解消する。

## 背景・なぜ

- CLAUDE.md のルール上、作業のたびに `Unreleased` へ追記するため、並行する PR は
  ほぼ必ず同じ行付近を編集し、コンフリクトが常態化していた。
- ロックファイルや CHANGELOG のような「追記中心のファイル」の衝突回避には、
  Git 組み込みの union マージドライバ（`merge=union`）を使うのが定番の解決策。
- カスタムマージドライバやマージ用スクリプトも検討対象になりうるが、
  `merge=union` は**追加設定・インストール不要**で、リポジトリの `.gitattributes` に
  1 行書くだけで全員・全環境（ローカルの merge / rebase / cherry-pick、GitHub 上のマージ）に効くため採用。

## 方針

- `.gitattributes` をリポジトリ直下に新設し、`docs/CHANGELOG.md merge=union` を指定する。
- `CLAUDE.md` の「ドキュメント」セクションにルールとして明記する
  （仕組みの説明・副作用・指定を消さないこと）。
- `docs/CHANGELOG.md` の `Unreleased` に変更内容を追記する。

## 経緯・メモ

- `merge=union` の副作用は「まれに行順が入れ替わる」程度。Keep a Changelog の
  セクション見出し（`### Added` 等）ごと重複することは通常なく、実害があれば
  リリース時に整えれば十分、という判断。
- コードの変更はないためテストは対象外。セキュリティ上の懸念もなし
  （マージ挙動の宣言のみで、実行コードを持たない）。
