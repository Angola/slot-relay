# SECURITY.md — セキュリティ懸念事項

> ルール: 新機能・変更でセキュリティ上の懸念が生じたら、必ず本ドキュメントに追記する（CLAUDE.md 参照）。
> 各項目は「懸念｜対策方針｜状況」の 3 列で管理し、対策を実装したら「状況」列を更新する。
> 状況の値は **対応済み / 一部対応 / 未実装 / 運用ルール化** から選ぶ。

## 1. 外部からの入力・Webhook

| 懸念 | 対策方針 | 状況 |
|---|---|---|
| 外部 Webhook の偽装リクエスト | 署名検証を必須化（不正は 401） | 未実装 |
| API への過剰リクエスト | レートリミット | 未実装 |

## 2. 認証・認可

| 懸念 | 対策方針 | 状況 |
|---|---|---|
| API の認証・なりすまし | <認証方式を記述（例: JWT / セッション）> | 未実装 |
| 越権・IDOR（他ユーザーのリソース参照） | すべて本人スコープでクエリする | 未実装 |
| CORS | 許可オリジンを ENV で明示 | 未実装 |

## 3. シークレット管理

| 懸念 | 対策方針 | 状況 |
|---|---|---|
| API キー・認証情報の漏洩 | リポジトリに平文で置かない。ENV / secrets マネージャに集約 | 未実装 |
| CI からの漏洩 | GitHub Secrets を使用。ログへのエコー禁止 | 未実装 |

## 4. ユーザーデータ・プライバシー

| 懸念 | 対策方針 | 状況 |
|---|---|---|
| 個人情報・機微情報の取り扱い | アクセス最小化・削除導線を用意 | 未実装 |
| 退会時のデータ残存 | 関連データを連鎖削除する | 未実装 |

## 5. サプライチェーン・依存関係

| 懸念 | 対策方針 | 状況 |
|---|---|---|
| 依存パッケージの脆弱性 | 依存監査を CI で実行（Dependabot 等） | 一部対応 |
| サードパーティ CI アクション | 公式アクション優先。サードパーティはコミット SHA でピン留め | 運用ルール化 |

## 6. LLM 特有のリスク（AI を使う場合）

> AI（LLM）を組み込むプロダクトでは、通常の入力検証に加えて次を検討する。使わないなら本節は削除してよい。

| 懸念 | 対策方針 | 状況 |
|---|---|---|
| プロンプトインジェクション（直接／間接＝外部データやツール出力経由でモデルを乗っ取る） | システムプロンプトを最優先と明示・信頼境界を分離（ユーザー入力/外部データを「命令」として扱わない）・入力の無害化 | 未実装 |
| Jailbreak・システムプロンプト逸脱（安全方針の回避） | 安全方針を常時注入し persona より優先・出力側モデレーション | 未実装 |
| システムプロンプト／秘密の漏えい（prompt leak） | 秘密（API キー・内部情報）をモデルの文脈に入れない・出力フィルタ | 未実装 |
| **LLM 出力を信頼して実行／描画**（XSS・SSRF・任意コード実行・SQL 生成の悪用） | モデル出力は**未信頼**として扱う。HTML はエスケープ、URL/コマンド/クエリは許可リスト・サンドボックス | 未実装 |
| ツール／エージェントの越権（tool abuse・危険な副作用） | ツールの権限最小化・破壊的操作は人間承認・呼べるツールを許可リスト化 | 未実装 |
| 学習データ／ログへの機微情報の混入 | プロンプト・応答ログに個人情報を残さない／マスク・保持期間を限定 | 未実装 |
| LLM 原価の暴走（攻撃・バグによる大量呼び出し） | レートリミット・トークン/回数上限・利用量の監視 | 未実装 |

## 更新ルール

- 機能追加・変更の PR では、本ドキュメントの該当セクションを見直し、新しい懸念があれば追記する
- 対策を実装したら「状況」列を更新する
